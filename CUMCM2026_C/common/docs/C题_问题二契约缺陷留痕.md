# 问题二契约缺陷留痕（队长记录）

> 用途：记录执行过程中发现的**契约自身缺陷**及其处置结论，供 t8 复核与最终归档参照。
> 这些缺陷**不是交付物的缺陷**——交付物按订正后的契约定稿，缺陷只存在于早期契约文本与任务记录中。

## D1 · 预报发布时刻写错（严重，已订正）

**缺陷**：契约 §5.4 原写"第 $d$ 天 0:00 制定计划时只能使用**前一日 18:00 发布**的预报"。

**为何是缺陷**：前一日 18:00 发布的那条 24 列覆盖 18:00(d−1) → 18:00(d)，**缺第 $d$ 日
18:00–24:00 共六列**，无法铺满当天；而第 $d$ 日 0:00 发布的那条恰好铺满全天 24 个整点小时块，
且 0:00 发布的预报在 0:00 制定计划时本就属于已得信息，不违反非预期性。

**发现者**：建模手（t5 阶段，指出 §5.4 第一条与 R-Q2-5 的公式不能同时成立）。

**处置**：§5.4 已订正为"第 $d$ 日 0:00 发布、覆盖 0:00–24:00 的 24 个整点小时块"；
代码由 t6/t10 对齐；§八.2 由 t7 对齐。

## D2 · 两个调度口径的"界"写反（严重，已订正）

**缺陷**：契约 §5.4 R-Q2-4 曾写"锁定调度是**下界意义上的保守值**，任何真实系统若在日内
获得新信息并调整只会**更低**"，并把日内再调度称为"完全预见下的**乐观下界**"。

**为何是缺陷**：与实测方向相反。同一预报口径（仅光伏不可知）下的终值：
**承诺调度 1 262 153.80 kWh ＜ 日内再调度 3 783 737.59 kWh**
（总费用 17 938 582.49 元 vs 21 169 622.42 元）。根因是二者**不是同一承诺结构下的松紧对比**：
只锁 $p$ 时计划阶段会为省 1 倍电价而多放，实际阶段再按 5 倍补缺口，反而更差，
且丧失完全信息下的可复现性。

**发现者**：编程手（首报方向相反）→ 建模手（定位为"两个变体不是松紧对比"）→
论文手（指出章面与实测冲突）。

**处置**：R-Q2-4 已订正为按**性质**定性——承诺调度口径 = 主线对照（资格 = 完全信息下精确
复现主模型），日内再调度口径 = 假设性对照（不具备该复现性）。
**现行规则**：任何文档、章节、JSON 不得用"上界/下界/乐观/保守"刻画这两个口径的关系；
技术性用法（"$p$ 不设上界""储电量上界 10 800 kWh""$\sum e$ 有下界"）不受此限。

## D3 · 数据泄漏误判（队长自身错误，已撤回）

**缺陷**：队长曾判定"附件 3 存在数据泄漏"，依据是"某发布时刻某段时效上预报与实际
**逐位相等比例 100%**"，并据此下发三方。

**为何是缺陷**：那些段**全部落在实际光伏恒为 0 的夜间时段**——两边都是 0，相等是必然的，
与预报是否复制实际值无关。正确的检验必须在**实际光伏非零的样本**上进行：按此口径，
54 个 $(r,k)$ 组合的逐位相等比例仅 0.3%–5%，与四位小数的舍入巧合一致，**不存在整段相等**。

**发现者**：论文手（坚持"不写不可复现的结论"，并给出严格判据与实际值样本要求）。

**处置**：结论撤回；契约改为"夜间低信息量事实（不要误读为数据泄漏）"并留误判留痕。
**教训**：判定相等性时必须先排除"两边同为 0"的平凡相等。

## D3b · 复核方法教训四条（**不构成产物缺陷**，但每条都实际误导过一次判断）

这一节记的是**读产物时的方法坑**，不是产物的问题。之所以单列，是因为四条各让复核者
（含队长本人）得出过一次**错误结论**，且都属于"数字看起来有出处、实际对不上"的同一类。
**请勿把本节条目当作产物缺陷**。

### （a）过滤必须用编号前缀，不可用标签子串

**误判**：队长按 `口径` 列的子串「仅光伏不可知」过滤 `Q2_emergency_detail.csv`，
求和得 **6 123 301.81 kWh**，与汇总的 1 262 153.80 kWh 差 **4.85 倍**，一度报为"源间不一致"。

**真相**：口径 ③④⑤ 的标签**都含该子串**——`③ 仅光伏不可知（负载已知）`、
`④ 仅光伏不可知 + 改用当天 6:00 发布的预报…`、`⑤【假设性对照】仅光伏不可知 + 允许日内再调度储能`。
按子串命中 **6 328 行 / 三个口径**，其和恰为
$1\,262\,153.80+1\,077\,410.42+3\,783\,737.59=6\,123\,301.81$，与误报数字**逐位相同**。
改用**编号前缀**精确匹配后，五个口径**全部与 JSON 汇总逐位吻合**
（③ 2 252 行 / 334 天、④ 2 256 行 / 334 天、⑤ 1 820 行 / 334 天、① 4 635 行 / 287 天、② 4 403 行 / 295 天），
全文件合计 11 831 965.19 kWh = 五口径之和，无重复行。**产物无缺陷。**

**规则**：对口径/分组列做筛选，一律用**编号前缀或等值匹配**；
本题的口径标签是**相互包含**的，**禁止**用标签子串。

### （b）别把负载当光伏

附件 2 的**小区负载**峰值在 3 300–6 000 kW 量级，与"光伏"容易混淆。曾据此给出
"附件 3 预报峰值 8 161 kW 远高于实际光伏约 1 400 kW"的**错误表述**。
实测：附件 2 光伏峰值 **10 216.20 kW**、99.9 分位 9 739.22、逐日最大值中位 8 161.05；
附件 3 预报峰值 **9 995.8875 kW**——**两者同尺度**。

**规则**：引用"峰值/量级"前先确认列名；kW 量纲下负载与光伏同在千 kW 级。

### （d）过期快照：读盘时文件正在被改写

本问至少出现**五次**"读到中间态却当成终态"：队长两次读到 `Q2_analysis.py` / 契约的旧版本，
建模手两次拿到契约中间态，编程手两次拿到任务板中间态。其中一次使建模手报出
"§5.4 仍有陈旧数值残留"的**不成立 finding**（随后自行撤回）。
最强的一次：求解章曾有**三个同为 460 行、字节各为 52 062 / 52 313 / 52 312 的版本**，
行数与行号完全相同，**只有字节数能分开**。

**规则**：① 报"未落地 / 有残留"前**再取一次快照**（比 mtime + 重读关键字段）；
**任何对版本的引用（含队长自己的状态行与回报）都须带该 artifact 自身的 mtime**，
格式固定为 `文件名 行数 行 / 字节数 字节 / mtime HH:MM:SS`——本问队长曾四次引用过期版本；
**（建模手订正，本条初版口径有误）**初版要求的是"带**取数时刻**"，那是**读的动作**，
只能证明"我读过"，无法证明"我读的就是现在这版"，读者也无从判断是否交叉；
**mtime 才是被读对象的属性**，可与任何一次改动直接比对：引用里的 mtime 一旦早于
该文件的最后改动，"取数 → 对方落盘 → 消息到达"这一交叉立刻可见。
本问末段即有一例真实竞态：队长引报告 `640 行 / 53 937 字节`，该值在其取数当刻**准确无误**，
但建模手随后于 06:00:10、06:00:20 两次落盘，消息到达时已过期。
**若按 mtime 引（05:59:02 对 06:00:20），交叉一眼可见，无需任何额外说明。**
② 产物侧统一以「**脚本 mtime 早于 JSON mtime**」为收口信号；
③ 判缺陷以**订正后的契约与两章正文**为准，不以任务记录旧文字为准（见 D5）；
④ **版本锚必须给五元组：`行数 / 字节数 / mtime / sha256_16`**（章节另加表号集合、占位符数），单指标不够；
　　**（本问末段由"四快照"升格，证据见下）**原规则为"行数 / 字节数 / 表号集合 / 占位符数"。
　　本问共实证 **4 例"等长改写"**（行数与字节数完全相同、内容不同）：
　　`_q2_field_path_check.json` 在 **776 行 / 26 191 字节**下先后出现三个 digest
　　（`8b8abb27…` → `caa8b23f…` → `399e8e27…`），又在 **777 行 / 26 214 字节**下出现两个
　　（`8c54ae9c…` → `3da6f724…`）。**按旧规则，这些版本会被判成同一个文件。**
　　**根源不是手误，而是产物自身的属性**——凡自带**定宽生成戳**的产物重跑即等长改写：
　　`_q2_audit_thirdparty.json.generated_at`（19 字符）、`_q2_field_path_check.json.generated_at`；
　　变相者还有**可变浮点**：`Q2_diagnostics.json.solver.elapsed_seconds`（33.23 → 33.33 已实证）、
　　`Q2_analysis.json` 六口径各带 `elapsed_seconds`。
　　⇒ **digest 是这套判据里唯一不能被"等长改写"绕过的一维。**
　　与「三个同为 460 行的版本」（52 062 / 52 313 / 52 312，**字节数尚能分开**）为同一方向、**更强一级**。
⑤ **同行数改动后必须复测行锚**（本问行号失效 3 处、受影响数值 0 个 → "行号会漂，数值不漂"）；
⑥ **行数须写明计数口径**：一律 `len(text.splitlines())`。本问末段实证同一文件
　　`splitlines()` = 285 而 `split('\n')` 元素数 = 286（末尾换行），
　　**两方数法不同时，"行数相同"这个判断本身就会失真**；
⑦ **引他人消息须粘原文，引版本须粘工具输出的一行状态行**——两者同一种纪律：
　　**引用必须带上可被对方机械核对的原始载体**。本问末段为"那条消息里到底写了什么"
　　空耗两轮：**有原件时可判（引文可核），只有记忆时不可判**；
⑧ **判据要挂在产物上，不要挂在消息上**——消息里的数字有保质期，产物里的快照没有。
　　验证配方一律写成"与**你手上那份产物内所记的值**比对"，不得写成"与消息里的数字比对"。

### （e）判据必须能被真违规触发（假阴性）

**误判**：§7.2 负向判据曾举 `1262153` 作为"结果数值不得出现在方法章"的检验串。
实测该串**两章皆 0 命中**——因为正文实际写作带分隔符的 `1 262 153`。
即这条判据的"0 命中"是**必然的、不携带信息**，永远为绿。

同类：`20218838` / `12245046` / `835960` 两章皆 0，而 `20 218 838` / `12 245 046` / `835 960`
在求解章分别有 13 / 11 / 9 次。

**规则**：写"期望 0 命中"前，先确认该串在本版正文里**确实会以违规形式出现**；
若违规写法另有其形，判据须**并列全部写法变体**，否则该条永远是绿的。
**判据的价值在于它能被触发。**

### （e2）变异测试：判据清单自身的验收方法（队长规则经建模手加强）

**起因**：队长原规则只要求"故意构造**一个**违规样本，确认**至少一条**判据会红"。
建模手指出**这太弱**——十条判据里只要有一条可触发，整轮也会"通过"，
而 `1262153` 这种**单条永远为绿**的问题照样漏掉。**结论：原规则作废，改用逐条变异测试。**

**五步法**：

1. **每条负向判据都要有它自己的一份违规样本**，且样本必须写出**真实违规形态**
   （不是把串随便塞进去——塞的形态若与判据串不匹配，测的就不是该判据）。
2. **对偶检查**：一份变异**只应让目标判据变红**；若同时红了别的判据，
   说明那条判据**过宽**（会误报）——这一半正好接上 7.3 的三类豁免。
3. **正向判据反向做**：删掉一条正向串，确认该判据**变绿**（证明它原本确实在检这处内容）。
4. **样本一律在临时副本上做**；两章已冻结，**绝不可就地改**。
5. 一轮跑完输出「**判据 × 变异**」矩阵，绿/红分布一目了然——**这份矩阵本身就是可交付的验收证据**。

**最小变异集（可沿用问题二踩过的坑）**：

| 编号 | 变异 | 目标判据 |
|---|---|---|
| M1 | 插入禁用串（`乐观下界` / `保守上界` / `上界式` 各一处） | 对应负向判据 |
| M2 | 往**求解章**插入**带分隔符**结果数值（如 `1 262 153`） | 该串的无分隔符判据应**不为红**（这正是 `1262153` 漏报的成因）；同时确认带分隔符判据本身在求解章**允许**、在方法章**禁止** |
| M3 | 往**方法章**插入**带分隔符**结果数值 | 方法-only 边界判据（须为该方法章判据的**真实违规形态**） |
| M4 | 把裸 `上界` 改成语义错误的 `上界式` | 验证裸词豁免不掩盖真违规 |
| M5 | 删一条正向串 | 该正向判据应变绿 |

**D3b(e) 与 D3b(e2) 的关系**：**(e) 是"判据可能不可触发"这个事实的发现；
(e2) 是防止这类问题再发生的通用验收方法。** 问题二当时**没做** (e2) 的第 1 步，
这就是漏掉 `1262153` 的原因。

**事实**（队长与论文手独立复算一致，样本 N = 48 096 个时段末储电量）：
求解章 §四印出的九个十分位，按 **Hyndman–Fan 第 6 型**（$p$ 分位取排序序列第 $p(N+1)$ 位线性插值，
= `statistics.quantiles` 默认 = numpy `method='weibull'`）可**逐位复现**；
改用 **第 7 型**（第 $p(N-1)+1$ 位，= numpy 默认 `linear`）则 9 个里有 **4 个**有差。

| 分组 | 分位 | 机制 |
|---|---|---|
| **相同：并列值（4 个）** | $p=0.2,0.4,0.7,0.9$ | 插值区间内两个次序统计量取值相同（落在 2 700 / 6 000 / 10 050 / 10 800 kWh 这类整齐值上） |
| **相同：两式位置恰好重合（1 个）** | $p=0.5$ | $2p-1=0 \Rightarrow p(N+1)=p(N-1)+1$，位置与权重全同（代数恒等） |
| **有差（4 个）** | $p=0.1,0.3,0.6,0.8$ | 插值位置不同且区间内无并列值；差值 0.0585 / 0.0685 / 0.0593 / **0.1112**（最大在第 8 分位） |

（"相同"合计 **5 个 = 并列值 4 + 两式重合 1**；上表按**机制**拆成两行，
避免单行标签里的个数与该行列出的分位数不符。）

任意分位网格（0.001 ~ 0.999，步长 0.001，共 **999** 点）上的最大差为 **1.3563 kWh**（出现在 $p=0.237$）。

**教训**：① 引用分位值时必须同时声明插值口径，否则读者按常见定义复算会得到不同的数；
② 描述"只有部分对不上"时要说清**机制**，不能只给个数——本问一度被写成
"numpy 五种方法都对不上"（不精确），实际是"只差 4 个，其余 5 个分属两种重合机制"；
③ 队长在给清单时曾把 $p=0.1$ 误列入"完全相同"，**由建模手实测纠正**——
**清单类结论也须逐项实跑，不能凭印象归纳**。

## D4 · 同一文件两套映射并存（严重，已订正）

**缺陷**：`Q2_analysis.py` 第 202 行用 `release_hour + k - 1`（在用分支），

`comparable_across_releases = false`，跨发布时刻的精度排序从结论段删除。

## D5 · 任务记录残留已被撤回的验收文字（低危，无法修改，仅留痕）

**现状**：t6 的 `problem` 描述与 t7 的验收第 3、4 条仍写着"锁定调度是保守（偏大）值、

## D8 · 收口阶段沉淀的方法论六条（**不构成产物缺陷**，全部有本问实证）

本问末段为"引用纪律"反复往返十余轮，最终沉淀出下面六条。它们不是产物缺陷，
而是**下一次可以省掉这些往返的东西**，故单列。

### （a）记录优于冻结

演化路径：**冻结** → 发现**观测者效应**（"报出工具输出"这个动作本身要运行一次工具，
一运行就重写输出、挂钟时间戳就变、digest 就变 ⇒ **为了引用而取数，取数改写了被引用对象**）
→ 实现**输入快照**（输出内记录"本次扫描消费的每个输入的指纹"）。
- **冻结**是"用禁止变化来保证可引用"——依赖各方自觉，**在多写方并行下反复失效**；
- **记录**是"用自描述来容纳变化"——**不依赖任何人停手**，读者自带判据。

⇒ **记录优于冻结；锚不必是"停止的状态"，可以是"带出处的历史"。**
**判据**：拿到一份旧引用时，能否从产物自身看出"它当时消费的是哪一版"。能，则机制成立。

### （b）开发期没有锚，只有发布期才有锚

锚**不是一个文件，而是一个被声明过停止的状态**。只要文件仍在编辑，
任何指纹声明在送达前必然过期——**这不是谁不小心，是"锚"这个概念在开发期不成立**。
本问实证：工具在七分钟内走了 v2.5 → v2.9 五版，**每一版都声明过"已冻结"**，
且逐版核到的都是新指纹。唯一可行时序：**先宣布停手 → 再取数 → 再声明**。

### （c）判据要挂在产物上，不要挂在消息上

消息里的数字有保质期，产物里的快照没有。
**验证配方必须写成"与你手上那份产物内所记的值比对"，不得写成"与消息里的数字比对"。**
本问实证：一条"可复现配方"发布后，任何人照跑都得到"不一致"——
**不是因为跑失败，而是因为消息里的值对应的是另一个输入状态**。

### （d）检查必须输出"被扫集合 + 逐类计数"

**空失败列表是零信息。**本问实证一：某检查输出 `doc_scan_unresolved: []`，
它有**三种不可区分的读法**：① 扫了 N 条、0 失败；② **一条也没扫到**、0 失败；
③ 若干条被宽容态容忍（**实际是这一种**）。
本问实证二：某工具的覆盖面**只含 2 个产物**，而缺陷指向第 3 个产物 ⇒
**"未扫到"与"扫到并通过"在只输出失败列表的检查里长得一模一样。**

⇒ **凡带"失败列表"的检查，必须同时输出被扫集合与逐类计数，否则"0 失败"不可被推翻。**
这与 D3b(e) 同族：**判据不可触发 ⇒ 恒绿 ⇒ 绿是零信息。**

### （e）"宽容态"是假绿的第二种成因（与 D3b(e) 并列）

D3b(e) 讲的是**判据不可能被触发**（如 `1262153`：无分隔符串在两章都不存在 ⇒ 恒绿）。
本问末段补上第二种：**判据可被触发，但被自身的宽容规则吸收**。实证：某路径检查器把
`variants[*].summary` 判为通过——因为 `[*]` 用在一个 **dict** 上时被当作"任意值"，
而它实为**语法不合法但被默许**的写法；另有 3 条被第三态"缩写引用"容忍。
⇒ **两种成因的共同点：绿的成因不可辨认，就等于没有检查。**
**验收要求**：宽容态必须**显式列举**（如 `ALLOWED_TOLERANCES = []` + 单列计数），
**不得内建为隐性规则**；且**引用 verdict 时必须同时给出三态计数**。

### （f）锚定物只能包含"本性稳定"的输入

**指纹是用来锚定"可被引用的东西"的；一个本性就要增长的文件，不该参与锚定。**
本问实证：某工具的输出指纹把一份**增长型记录**（审计记录 md，按条追加）算进了载荷，
于是"记录一涨 ⇒ 指纹就变"，**任何引用配方都不可能成立**。
改为 `fingerprint_excluded`（**仍扫描、仍在 `inputs` 留痕，只是不参与指纹**）后：
记录档从 328 行长到 330 行，重算指纹**不变** ⇒ 机制成立。
⇒ 与之配套的三分口径：**手写件**（两章、报告）→ 内容五元组即锚；
**机器产物** → 至少"产出时刻 + 指纹"，更好是"输入快照"；
**增长型记录** → **不作锚、不对外报指纹**，引用写"该记录 §X（引用时刻）"或当场现取。

### （g）编码崩溃的零风险治理：**"硬编码"应做在调用层，不是改脚本**

`PYTHONIOENCODING` 一事本问两次咬人：`Q2_audit.py` 崩在 `\u207b`（上标负号），
一次**一次性核验命令**崩在 `⇒`（U+21D2）。原 R-Q2-8 的措辞只覆盖"常驻脚本"，
**应扩到"一次性核验命令"**。
**但"给 7 个脚本各加两行兜底"是错的治理方向**：改脚本会反转
t10 的硬不变量「**脚本 mtime < 其产物 mtime**」（当前四对全部成立），
并连带使 `_q2_audit_thirdparty.json` 等复核基准全部换戳——
**为防一次崩溃而让整条验证栈失效，代价与收益完全不成比例。**
⇒ **正确做法**：① **调用层**统一设 `PYTHONIOENCODING=utf-8`（共享校验器与命令行都在调用层，
改它零风险、不牵动任何产物）；② **新脚本**（问题三起）写进模板作为约定；
③ `errors='replace'` **不得使用**——它会把不可编码字符变成 `?`，
**若被替换的恰好是数字，输出会失真**；须用 `errors='backslashreplace'`（变成 `\uXXXX`，信息不丢）。
