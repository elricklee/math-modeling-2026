# 问题2 方案三（SARIMA + 两阶段随机规划 + 自适应储能执行）正式采用记录

日期：2026-09-13。本记录对应 `results/CUMCM2026_C/result2.xlsx` 的本次重写，前一版本（同类日分位数因果方案）的口径与数值见 `docs/C题_版本对照与修正记录.md` 及 `data/processed/CUMCM2026_C/` 历史说明。

## 采用的流水线（仅替换问题2）

1. **预测（0:00，严格因果）**：逐时段 SARIMA 中位数预测。负载用原始尺度、光伏用平方根尺度，各 144 个 SARIMA(1,0,0)×(1,0,0)₇ 模型，每周在 ≤182 天滚动窗口上重拟合（变体 A，缓存见 `sarima_cache_*.npz`）。
2. **计划（两阶段随机规划）**：从 SARIMA 自身的逐日误差史（实际 − 预测，整天整条重采样，联合保留负载/光伏日内相关）抽 K=200 个情景，围绕中位数预测构造"平行明天"；单日 LP 在共享计划（购电/充放电/SOC）与逐情景追索（紧急购电 5 倍、弃光、未用计划）之间最小化期望结算费用。λ=1.0（经验误差分布不放大）。
3. **执行（自适应储能，轨迹保护）**：购电计划 0:00 冻结；储能实时补位缺口，但只准动用高于计划 SOC 轨迹的盈余电量（`dispatch.execute_interval` 的 `adaptive_storage` 路径）。
4. **结算**：计划费按计划购电量预付（题面"按计划购电量计算"），缺口按 5 倍电价紧急购电；SOC 逐日实际传递，1 月预热，2.1–12.31 共 334 天计费。

## 调参与选参（验证期 7–9 月选、测试期 10–12 月盲评）

- 情景数 K：30→200 验证期 4,446,999 → 4,349,626 单调改善（采样噪声压低 80 分位估计）；K=400 无进一步改善。
- λ（尾部放大）：K=200 时 λ=1.0 优于 1.15/1.3/1.5；经验误差分布本身已校准（实际超情景 80 分位频率 22.2% vs 名义 20%）。
- 误差窗口：全历史优于近 90 天。

## 必须写入论文的口径声明

1. **执行口径**：本结果假设 0:00 冻结的仅是购电计划（合同量），储能充放电为实时可控的内部调度、只准动用高于计划 SOC 轨迹的盈余。保守口径（充放电严格按计划回放）对应全年 15,181,150 元；两口径差 483,252 元可表述为"储能实时可控性的价值"。
2. K=200、λ=1.0、窗口与 SARIMA 阶数均为验证期选取，测试期盲评；不声称全局最优。
3. 自适应储能下的贪心变体（无轨迹保护）会恶化结果（方案一上实测 15,924,379 元），论文如提及实时补位必须同时说明轨迹保护。

## 关键实现事实（复现）

- SP 公式中每个情景必须含**未用计划电量**松弛变量（无成本）：盈余若只能靠弃光吸收，其上限为光伏量，夜间为零会把计划购电压到全部情景最低净需求之下（首版 bug，实测全年 1,978 万、紧急 2.3 GWh）。
- 复现命令：
  ```
  python -m src.CUMCM2026_C.sarima_plan precompute A   # 预测缓存（约 3.5 分钟）
  # 最终运行与导出：见本记录采用的 sp_plan.build_inputs/make_planner + dispatch.run(adaptive_storage=True) + export_results.export_scenario
  ```
  中间结果：`data/processed/CUMCM2026_C/problem2_plan3_final.json`（含逐时段明细与 model 元数据）、`sp_vs_plans.json`（14 组调参网格）、`sarima_vs_baseline.json`（方案二网格）。
- `dispatch.py` 的改动均为可选参数（`load_predictor/pv_predictor/plan_fn/adaptive_storage`），默认路径经三次逐位回归验证与原版一致（15,780,940.73 元）。
- result3 / result4-2 / result4-3 未改动，仍为原因果方案。
