### A4 `result1` 行口径 → 方案 A

实测 `result1.xlsx` `计划购电量`：`145 × 2`，144 个数据行，首行 `0:10-0:20`，末行 `0:00+1-0:10+1`，裸 `0:00-0:10` 出现 **0** 次。

精确差异（**采纳论文手的更精确表述，修正编程手的"整体左移一格"**）：
- 模板**缺当日 `t=1`（`0:00-0:10`）**；
- 模板末行是**次日首时段** `0:00+1-0:10+1`；
- 故 `result1` 第 `r` 行 = 附件1 口径的**区间 `r+1`**（r = 1..144）。

**裁定：方案 A** —— 写 144 行，行标签用附件1 口径 `0:00-0:10 … 23:50-0:00+1`，第 `r` 行写 `t = r` 的购电量。理由：`0:00-0:10` 是必须以 0:00 为起点优化并报送的决策量，照模板口径会整段丢弃；仍保持 144 行，与模板行数一致。
**必须在文档与代码注释中显式声明该差异**（编程手已在 `io.result1_row_labels()` 加 `warning` 并新增 `result1_row_labels_decision()`，已落地）。

### A8 限光变量：**模型必须允许弃光，但无需显式变量**

**这是本轮最关键的模型正确性问题。**

- 建模手主张：必须引入限光松弛 `g_t`，否则不可行。其论据为"附件1 中午净负荷低至 −2117.5 kWh，是单时段上限 833.3333 的 2.54 倍"。
- **该论据量纲有误**：`−2117.5` 是**功率（kW）**，不是**电量（kWh）**。换算 `×Δt = 1/6` 后为 **−352.92 kWh/时段**，仅为吸收上限 833.3333 kWh 的 **42%**。队长实测：**无一时段超过吸收上限**。
- 但**结论方向仍正确**：题面约束是"微网提供的电能**不可低于**小区负载"（不等式），配合"不允许光伏上网"，物理上光伏余量确实可能无法被吸收 —— 只是**无需显式引入变量**，把功率平衡写成**不等式**（`p_t ≥ net_t + x_t − y_t`）即可自然表达弃光。
- **队长独立 LP 实测结果：最优解限光 = 0.0000 kWh**（全天负余量 6 247.96 kWh 全部被储能吸收，单时段最大 352.92 kWh < 833.33 kWh，且 SOC 足有空间）。

⇒ 裁定：**模型采用不等式平衡口径**；限光作为**可选松弛**保留在模型描述中（用于讨论可行性与"若允许上网"的对照口径），但不要把"必须限光"作为模型必要性的论据写入论文，否则会被证伪。**若写成显式变量，最优解中该变量取 0，并非"必需"。**

### A20 队长更正：把建模手的 0.952 判为"混口径"是错的

### A21 队长更正：问题1 参考解存在 SOC 递推缺陷（已作废并重算）

**争议**：队长初版问题1 参考解为 58 909.39 kWh / 34 886.19 元，并自报"残差 ≤ 2.3e-13"。编程手以 `Σy/Σx = 0.9463 ≠ η² = 0.81`、建模手以 `residual_soc = 1590.34` 分别提出异常。

**裁定：两位成员均正确，队长初版作废。**

**缺陷定位（队长自查确认）**：初版 `build()` 中 SOC 递推写成 `for t in range(1, T)`，只生成 143 行，且行索引相对时段偏一格 ⇒
1. **漏掉一个时段的递推约束**（`t=123` 的递推无任何行覆盖，实测 `residual_soc = 1590.34` 正出现在该处）；
2. `S_0 = S_INIT` 被写成**硬等式**，使 **时段 0 的 `x_0`、`y_0` 不进入任何守恒关系** ⇒ 求解器"免费"放电：实测 `y_0 = 573.31 kWh` 而 `S_0` 仍被钉在 6000，**凭空产生能量**；

- 重建为 `S_0..S_144` 共 145 个状态变量 + `x, y, g` 各 144 个（n = 577），SOC 递推**覆盖 t = 1..144 全部 144 个时段**，`S_0` 与 `S_144` 均钉死为 6000。

### A12 紧急购电恒为 0

### A13 `调整购电量` 语义（R5）

**裁定："修正后最终执行的购电量"**，不是"修正差值"。理由：题目要求 `计划购电费 + 紧急购电费 + 调整相关费用` 求和，而"调整购电量高于计划的部分按 1.5 倍、低于计划的部分按 50%"必须以两份**可比的购电量序列**（计划 vs 调整）为前提；若 `调整购电量` 存差值，则 50%/1.5 倍的比较基准无法从文件本身还原。
费用口径：
```
总费用 = Σ_t c_t·p^plan_t                                 计划购电费
       + Σ_t 5·c_t·z_t                                    紧急购电费
       + Σ_t 1.5·c_t·max(p^adj_t − p^plan_t, 0)
       + Σ_t 0.5·c_t·max(p^plan_t − p^adj_t, 0)
```
`调整购电量` 工作表填 `p^adj_t`。

### 5.4.2 ⚠️ 一处需收尾的验收项：`residual_soc`

同一输出中 `residual_soc = 1590.3400740740733`，而其 JSON 记录与 A9 对照表宣称
"残差 ≤ 2.3e-13"。编程手分析：

* **解本身物理可行**：由该解回算 `Σy / Σx = 17 373.25 / 20 740.67 = 0.83764`，
  而 `η² = 0.81`；两者不等，说明该模型的 SOC 递推在 576 变量化简中
  对 `x_t, y_t` 采用了**带 Δt 的等价形式**（`Δt·x`、`Δt·y` 参与递推）。
* 因此 `residual_soc` 很可能是**另一套（未缩放）口径下的诊断量**，而非真实违反；
  但既然它被清楚地打印出来，就可能误导后续实现者。
* 编程手在自建 720 变量模型中改用完整守恒式
  `Σp + Σpv·Δt − Σload·Δt − Σg + (W0 − W144) = (1−η)Σx + (1/η−1)Σy`
  做验收，残差 `3.6e-12`，且 `Σy/Σx = 0.810000` 精确成立。

**建议（不阻塞契约）**：在 `lp_p1_final.py` 与 A9 对照表中，
把 `residual_soc` 的**口径**写明（哪个方程、是否含 Δt 缩放），
或改用一个自洽的诊断量，避免"A9 说残差 1e-13，实跑却打印 1590"的观感冲突。

> ✅ **队长补注（收敛后，本条已闭环）**：编程手提出的疑点**是真实缺陷**，不是口径问题 —— 但**其推测的原因（"带 Δt 的等价形式"）不对**。

> 修正后 `residual_soc = 8.74e-13`，`Σy/Σx = 0.81`。**本节结论已失效，保留作为追溯记录。**
